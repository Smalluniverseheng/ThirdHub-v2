# 第 4 代 · ThirdHub v4 更新日志（重排版）

> 当前主力：局域网设备编排——前端纯播放器 + 后端资源库 + 独立引擎 App，THP 协议匿名接入，新引擎零改动接入前后端。

### v4.42.0　2026-09-21　🔶 里程碑

- AI 架构升级：Agent 内核不再自己造。把 DeepSeek Harness（DSH）放在后端 / 局域网设备上跑 Agent 运行时，App 只做控制面——发起任务、渲染事件流、批准高危操作、看审计。设备上没装 DSH 时自动降级为轻量 Agent，并**明确告诉用户现在缺哪些能力**，不会把按钮画得能点、点下去却什么都不发生
- 任务栏（智能体 → 任务）：一处看全运行模式与能力矩阵（哪些能力真的可用）、切权限档位并预览该档位下每个工具是「可执行 / 需确认 / 禁用」、按顺序渲染四类事件（助手流式正文 / 工具调用含风险等级与参数 / 确认请求 / 工具结果与产物）、高危操作就地「允许一次 / 拒绝」、查看最近审计留痕
- 权限三档：默认（只读 + 草稿）/ 本次会话接受修改 / 完全访问（仅服务端管理侧，普通用户看不到）。判定顺序固定为「档位存在性 → 显式禁用 → 风险等级是否被覆盖 → 是否需确认 → 放行」；**服务端为权威**，客户端镜像只用于提前把按钮画成灰或标「需确认」；档位名写错一律按拒绝处理，不会静默放宽
- 事件协议（THA/1）：追加式事件日志，一处写入、可溯源；`contextRefs` 只上报引用（选中文本 / 书架书目 / 服务端文件 / 知识库页）而不搬运大段正文；长连接被中间设备掐断时可按序号补齐，不丢事件
- MCP 治理：MCP 服务改为在服务端登记与调用（凭据与连接不落到手机上），一页同时管「后端托管」与「本机直连」两条来源并说明分别适用什么场景；不跑 stdio
- 插件白名单与许可证红线：MIT / Apache-2.0 / BSD / ISC 放行，LGPL / MPL 谨慎，GPL / AGPL / SSPL / BUSL 进拒绝名单；缺许可证的插件不装
- 仓库安全：签名密钥（keystore 与口令）移出仓库并加入忽略清单；tag 出包改为从仓库密钥变量还原签名材料，密钥不再随代码分发。该密钥曾出现在公开仓库，建议轮换
- 新增《Agent 协议》文档与协议自检流水线：服务端 88 条断言 + 客户端 140 条断言（含与服务端权限表逐工具对拍，防「界面显示可点、服务端却拒绝」的漂移）
