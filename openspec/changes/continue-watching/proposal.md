# 提案：继续观看（Continue Watching）

## 为什么

搜索页是 App 的默认落地页。当前进来看到的是「空输入框 + 推荐带」，想接着看上次没看完的那一集，
必须自己去 视频 → 历史 → 翻列表。这是大厂首页一定会占的一格（Netflix 的 Continue Watching、
B 站/爱奇艺的「观看历史」、网易云的「最近播放」），而这里一直是空的。

体检时还发现一个更硬的问题：**「最近播放」列表的每一行根本没有 `onTap`** ——
记录能看不能点，用户点了完全没反应，而且没有任何提示。这不是缺功能，是缺陷。

## 变更内容

- 新增「继续上次」横滑带（`lib/core/continue_rail.dart`），复用已有的 `Recents` 数据源。
- 挂在搜索页类型筛选之下、推荐带之上 —— 默认落地页的第一屏。
- 卡片点击走统一路由 `openRecentEntry`：
  - `video` + 本地路径 → 本地视频播放器（播放器按 `vpos_*` 自行恢复进度）
  - `music` / `radio` + 可播地址 → 音乐播放器（按 `mpos_*` 恢复进度）
  - `audiobook` 或没有 target → 回对应模块（不假装能定位到某一集）
  - 模块不在底部导航 → 明确提示去「我的 → 功能管理」开启，**不静默**
- 「最近播放」列表补上 `onTap`，与横滑带共用同一份路由规则。
- 长按卡片可移除单条记录。

## 不在范围内

- 手势滑删、卡片封面图（`Recents` 目前不存封面，加封面要改写入侧四个调用点，单独提）。
- 跨设备「继续观看」（依赖进度冲突合并，属另一项债务）。
- 有声书定位到具体某一集（需要章节解析）。

## 影响

| 项 | 说明 |
|---|---|
| 模块成熟度 | 搜索 R2 → R2（补齐大厂首页位）；「最近播放」从缺陷修复到可用 |
| 后端依赖 | **零**。数据全部来自本机 SharedPreferences |
| 新增 i18n 键 | 4 个 × 6 语言（继续上次 / 最近播放 / 已移除 / 模块未开启提示） |
| 风险 | 组件读失败一律当空，不影响搜索页渲染 |
