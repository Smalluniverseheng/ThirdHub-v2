## 1. 为什么需要 `revoked`（这是本包第 2 版补上的关键）

`importPreset()` 原本是**只增不减**的：判据只有「这个 `bookSourceUrl` 在不在 sources 里」。
后果是——**把烂源从包里剔掉，对老安装完全无效**：老安装 `data/sources.json` 里那条烂源还在、而且
`enabled: true`，换包只是又追加几条新源，用户看到的一堆「搜得出、点进去是文字墙」的源照样在。

所以本包不仅有「白名单」`sources`，还有一条**撤销通道** `revoked`：

- 撤销动作是 **`enabled: false` + 组名改成 `已停用·双闸门未通过`**，**不是删除**。
  用户的源列表是他自己的数据；停用可以手动再打开。
- 包**没变**就完全不动（尊重用户删改）；用户手动重新启用的源不会被再次停用
  （因为标记是内容哈希，哈希没变就不再处理这份包）。
- 源重新回到白名单时会 **恢复 `enabled` 并把组名还原**（旧组名记在标记文件里，不塞进源对象）。
- 恢复/停用的簿记（原组名、原因、时间）全部存在 `data/preset-imported.json`，
  **`data/sources.json` 里只有 Legado 本来就有的 `enabled` / `bookSourceGroup` 两个字段被改**。

**已知边界（下一轮可做）**：同名 URL 已存在时，本机制**不会刷新它的规则**（只补新源 + 管启停）。
所以如果哪天修了某条已发源的规则，老安装不会自动拿到 —— 需要人工删掉该源再让包重新导入。

## 2. `sources` 是怎么挑出来的（双闸门，两道都过才进包）

第十轮实测过一个反例：**12 条「引擎口径能搜出书」的源里，只有 2 条真能干净地读**。
「搜得出」和「读得了」是两件事，所以本包的判据是两道硬闸门：

| 闸门 | 内容 |
|---|---|
| **① 搜索** | `engine.search()` 真解析出「书名 + 链接」（`search()` 末尾 `filter(b => b.name && b.bookUrl)`，规则走不完的源会被丢掉） |
| **② 逐页** | `engine.detail → catalog → content`，取**首章 + 中段章**（只验首章会把「正文页可用」验漏） |

闸门 ② 的合格线：目录 > 0 章；目录条目 `name`/`url` 齐备 ≥ 90%；章节 url 是绝对 http(s)；
正文 ≥ 200 字、**已分段（≥ 3 段）**、单章 ≤ 2 万字、**不是脚本残留**、**开头不是页面杂质**。

工具（都在 `D:/ai/_probe/`）：

```
# 大网捞候选（按社区评分 weight 降序取，命中率高得多）
node _curate_sources2.cjs <大源包> <输出> <候选上限> <并发> <关键词,逗号分隔>
# 收口：探实际书页域名、归一化去重、生成 {sources, revoked}
node _curate_publish_pack.cjs <干净源包> <老包> <输出> --rev N <净化meta...>
# 确认轮：把**最终包本身**再整包验一遍（必须 100%）
CURATE_EXISTING=<最终包> node _curate_sources2.cjs - <输出> 0 8 <关键词...>
```

## 3. rev 2 溯源（2026-09-25 · 第十二轮）

- **候选池**：`D:/ai/deep seek/sources-packs/sources-book.json` 共 2703 条（其中 2175 条有
  `searchUrl` + 名字），按 **`weight` 降序**（社区评分 0~940）取前 **1326 条**（按 host 去重后）
  ＋ 旧包 12 条**全部**纳入候选（含既有源二次机会，防网络抖动误判）。
- **关键词 8 个**：`斗破苍穹 / 剑来 / 都市 / 总裁 / 赘婿 / 斗罗大陆 / 完美世界 / 遮天`（任一命中即算过闸门 ①）。
  多关键词是为了给「总裁 / 历史」这类专精站公平机会，否则会被误判成搜索失败。
- **结果**：**1326 条 → 过闸门 17 条**（耗时 821s）。未过分布：`search × 1102 | timeout × 122 | toc × 74 | content × 11`。
- **收口**：归一化去重掉 2 条（`http://m.rulianshi.la` 与 `...la/` 这类只差结尾斜杠的重复）
  → **最终 15 条，落在 14 个独立书库**；确认轮 **15/15 PASS**。
- **撤销 10 条**：旧包 12 条里 9 条未过闸门（原因见 `revoked[].reason`）＋ 内置演示源。

### 为什么 1102 条卡在「搜索 0 条」不是引擎的锅

抽 20 条失败的源，用**和引擎同一套 URL 构造**在本机直连取一次搜索页，取证分类
（`_search_fail_forensics.cjs`）：

| 分类 | 条数 | 含义 |
|---|---|---|
| `DEAD` | 6 | DNS / 连接失败，域名已经没了 |
| `BLOCKED` | 7 | 404 / 429 / 503，站点在但搜索入口已废或被风控 |
| `STALE` | 4 | 200 且页面在，但**搜索页已不含关键词**（改版 / 参数过时） |
| `NOURL` | 2 | `searchUrl` 里是**没被替换的占位符**（源本身就是坏的） |
| **`RULE_GAP`** | **1** | 站点在、关键词也在，纯粹是规则选择器匹配不到 ← **只有这类才值得动引擎** |

**19/20 都是源侧失效，只有 1 条是规则缺口** → 结论：这条线的瓶颈在**源**，不在引擎。
这也正是本包选择「大网重挑源」而不是「继续改引擎」的依据。

## 4. 发布纪律

`health-book.json` **同时内嵌在两个交付物里**，改了必须**两个都重发**：

1. 后端发布 zip（`_pack_backend.mjs` → `_smoke_backend_zip.mjs` → 桶两道 + Release）
2. 后端 Android APK（`android/app/src/main/assets/` 里的那份 server 拷贝）

`_pack_backend.mjs` 已加硬闸门：包内 `health-book.json` 的干净源 **< 3 条**、
或**没有 `revoked`**、或 `index.js` 没调用 `planPresetSync` → 直接拒绝打包。
（「改了但没生效」是最容易静默漏掉的一类缺陷，所以写成闸门而不是写在文档里。）
