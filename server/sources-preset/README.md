# server/sources-preset/ —— 预置书源包（首启/新增时自动增量导入）

导入逻辑在 `index.js` 的 `importPreset()`：按「包文件名 + 条目数」记标记
（`server/data/preset-imported.json`），**包有变化才增量导入**；包没变就不动
（所以用户自己删掉的源不会被每次重启塞回来）。

| 文件 | 内容 | 来源 |
|---|---|---|

| `health-book.json` | **12 条经引擎口径实测可用的书源**（见下） | 2026-09-25 生成 |

## health-book.json 溯源（2026-09-25）

**它不是什么**：不是「网上抄来的源包」，也不是「按 URL 探活挑的源」。
`tools/source-health.cjs` 的判定走**站点同源中继（CF Worker `/api/proxy`）**，
而家庭后端的 `engine.js` 是**从这台机器直连源站** —— 两者网络出口不同，
且前者只验证「搜索页 HTML 里有没有这个关键词」，**不验证引擎能否解析出书**。
实测差距很大：中继口径 29/300 通过，引擎口径只有 3/29 真出结果。

**生成步骤**（可复现）：

```
# ① 中继口径先筛一遍（只当候选，不当结论）
node D:/ai/deep\ seek/tools/source-health.cjs --n 300 --conc 12 \
     --out <报告> --out-pack <候选包>
#    → 抽测 300 条，可用 29 条（10%）
# ② 引擎口径复验（真值）：直接跑 server/engine.js 的 search()
node D:/ai/_probe/engine_source_verify.cjs <候选包> <输出包> 斗破苍穹,剑来,都市
#    → 29 条候选里 12 条真解析出书（41%），共 545 条结果
```

- 关键词：`斗破苍穹` / `剑来` / `都市`（任一命中即算通过）。
- 只有 `engine.search()` 真解析出「书名 + 链接」的源才进包（`search()` 末尾
  有 `filter(b => b.name && b.bookUrl)`，规则走不完的源会被它丢掉）。

**这一版同时修掉了 `engine.js` 三处规则语义缺口**（否则只有 3/12 能跑）：
1. **`##` 后处理**（Legado 标准语义，缺失导致 `Expected name, found ##…`）—— 22/29 条源受影响；
2. **裸名段当标签名**（原来 `a`/`h2` 被当成 `.a`/`.h2`）—— 「站点 200 且有内容、引擎却 0 条」的头号成因；
3. **字段规则首段自匹配**（`bookList` 的选择器在字段规则里再写一遍时，`find()` 只搜后代会取空）
   ＋ 搜索地址占位补齐（`{{page}}`/`{{keyword}}`/`$keyword` 等）＋ `textNodes` 算子。

**统计口径说明**：这是「300 条抽样里活下来的」，**样本率不能外推成「全库 41% 可用」**。
真要大覆盖就加大 `--n`（全量 `--full` 约 60 分钟），再跑一遍 ② 复验。
